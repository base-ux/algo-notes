# Хэширование и хэш-таблицы

## Таблицы с прямой адресацией

Прямая адресация представляет собой простую технологию, которая хорошо работает
для небольших совокупностей ключей.
Если _U = {0, 1, ..., m-1}_, где _m_ не слишком велико, есть совокупность ключей,
то для представления динамического множества используется массив, или
**таблица с прямой адресацией**, обозначаемый _T[0 .. m - 1]_, каждая позиция,
или ячейка, которого соответствует ключу из совокупности ключей _U_.
Ячейка _k_ указывает на элемент множества с ключом _k_.
Если множество не содержит элемента с ключом _k_, то _T[k] == NIL_.
Реализация словарных операций тривиальна:
```
search(T, k)
    Вход:
        T: массив таблицы
        k: искомый ключ
    Выход:
        содержимое ячейки таблицы с искомым ключом или NIL

    return T[k]
```
```
insert(T, k, x)
    Вход:
        T: массив таблицы
        k: ключ для вставляемого элемента
        x: вставляемый элемент

    T[k] := x
```
```
delete(T, k)
    Вход:
        T: массив таблицы
        k: ключ для удаляемого элемента

    T[k] := NIL
```

## Хэш-таблицы

В случае прямой адресации элемент с ключом _k_ хранится в ячейке _k_.
При хэшировании этот элемент хранится в ячейке _h(k)_, т.е. используется
**хэш-функция** _h_ для вычисления ячейки для данного ключа _k_.
Функция _h_ отображает совокупность ключей _U_ на ячейки **хэш-таблицы**
_T[0 .. m - 1]_:

> _h: U -> {0, 1, ..., m - 1}_

где размер _m_ хэш-таблицы обычно гораздо меньше значения _|U|_.
Говорится, что элемент с ключом _k_ **хэшируется** в ячейку _h(k)_;
величина _h(k)_ называется **хэш-значением** ключа _k_.
Цель хэш-функции состоит в том, чтобы уменьшить рабочий диапазон индексов массива,
и вместо размера _|U|_ значений можно обойтись всего лишь размером _m_.
Ситуация, в которой два ключа могут быть хэшированы в одну и ту же ячейку,
называется **коллизией**.
**Коэффициент заполнения** _&alpha;_ есть отношение количества хранимых
элементов _n_ к размеру хэш-таблицы _m_.
При методе открытой адресации _&alpha; &le; 1_, при методе цепочек может быть
больше единицы.

## Хэш-функции

### Метод деления

Построение хэш-функции методом деления состоит в отображении ключа _k_ в одну из
ячеек _m_ путём получения остатка от деления _k_ на _m_, т.е. хэш-функция имеет вид

> _h(k) = k mod m_

При использовании данного метода лучше избегать некоторых значений _m_, например,
_m_ не должно быть степенью 2, поскольку если _m = 2^p_, то _h(k)_ представляет
собой просто _p_ младших битов числа _k_.
Зачастую хорошие результаты можно получить, выбирая в качестве значения _m_
простое число, достаточно далёкое от степени двойки.

### Универсальное хэширование

Подход, который называется универсальным хэшированием, заключается в случайном
выборе хэш-функции из некоторого тщательно отобранного класса функций в начале
работы программы.
Такой выбор не зависит от того, с какими именно ключами хэш-функции предстоит
работать.

Пусть _H_ - конечное множество хэш-функций, которые отображают данную
совокупность ключей _U_ в диапазон _{0, 1, ..., m - 1}_.
Такое множество называется универсальным, если для каждой пары различных ключей
_h, l &isin; U_ количество хэш-функций _h &isin; H_, для которых _h(k) = h(l)_,
не превышает _|H| / m_.

Построить такое множество довольно просто.
Пусть _p_ - простое число, достаточно большое, чтобы все возможные ключи
находились в диапазоне от 0 до _p - 1_ включительно.
Пусть _Zp_ обозначает множество _{0, 1, ..., p - 1}_, а _Zp*_ - множество
_{1, 2, ..., p - 1}_.
Из предположения о том, что пространство ключей больше, чем количество ячеек
в хэш-таблице, следует, что _p &gt; m_.
Определение хэш-функции _hab_ для любых _a &isin; Zp*_ и _b &isin; Zp_,
использующее линейное преобразование с последующим приведением по модулю _p_,
а затем по модулю _m_:

> _hab(k) = ((ak + b) mod p) mod m_

Семейство всех таких функций образует множество

> _Hpm = { hab : a &isin; Zp* и b &isin; Zp }_

Каждая функция _hab_ отображает _Zp_ в _Zm_.
Этот класс хэш-функций обладает тем свойством, что размер _m_ выходного диапазона
произволен и не обязательно представляет собой простое число.
Поскольку число _a_ можно выбрать _p - 1_ способом, а число _b_ - _p_ способами,
всего во множестве _Hpm_ содержится _p &sdot; (p - 1)_ хэш-функций.

## Метод цепочек

При разрешении коллизий с помощью цепочек элементы, хэшированные в одну и ту же
ячейку, помещаются в связанный список.
Ячейка _j_ содержит указатель на структуру списка всех элементов, хэш-значение
ключа которых равно _j_; если таких элементов нет, то ячейка содержит _NIL_.
Реализация словарных операций простая:
```
search(T, k)
    Вход:
        T: массив хэш-таблицы
        k: объект, содержащий искомые данные (ключ)
    Выход:
        указатель на объект с искомым ключом или NIL

    j := h(k)
    return list-search(T[j], k)
```
```
insert(T, k)
    Вход:
        T: массив хэш-таблицы
        k: вставляемый объект

    j := h(k)
    list-insert-first(T[j], k)
```
```
delete(T, k)
    Вход:
        T: массив хэш-таблицы
        k: удаляемый объект

    j := h(k)
    list-delete(T[j], k)
```

## Открытая адресация

При использовании метода открытой адресации все элементы хранятся непосредственно
в хэш-таблице, т.е. каждая запись таблицы содержит либо элемент динамического множества,
либо значение _NIL_, либо специальное значение _DELETED_ для удалённых элементов.
При поиске элемента систематически проверяются ячейки таблицы до тех пор, пока не
найдётся искомый элемент или пока не будет обнаружено его отсутствие.

Для выполнения вставки при открытой адресации последовательно проверяются, или
исследуются (probe), ячейки хэш-таблицы до тех пор, пока на найдётся пустая ячейка,
в которую помещается вставляемый ключ.
Последовательность исследуемых ячеек зависит от вставляемого в таблицу ключа.
Для определения исследуемых ячеек хэш-функция расширяется вторым аргументом с номером
исследования (начинающегося с 0):

> _h : U &times; {0, 1, ..., m - 1} -> {0, 1, ..., m - 1}_

В методе открытой адресации требуется, чтобы для каждого ключа _k_ последовательность
исследований

> _&lt;h(k, 0), h(k, 1), ..., h(k, m - 1)&gt;_

представляла собой перестановку множества _&lt;0, 1, ..., m - 1&gt;_, чтобы в конечном
счёте могли быть просмотрены все ячейки хэш-таблицы.

Пусть задана обычная хэш-функция _h' : U -> {0, 1, ..., m - 1}_, которая в дальнейшем
будет именоваться вспомогательной хэш-функцией.

### Линейное исследование

Метод линейного исследования для вычисления последовательности исследований использует
хэш-функцию

> _h(k, i) = (h'(k) + i) mod m_

для _i = 0, 1, ..., m - 1_.
Для данного ключа _k_ первой исследуемой ячейкой является _T[h'(k)]_, далее исследуются
ячейки _T[h'(k) + 1]_ и последовательно все ячейки до _T[m - 1]_, после чего
происходит переход в начало таблицы и исследуются ячейки _T[0]_, _T[1]_, ..., _T[h'(k) - 1]_.
Линейное исследование легко реализуется, однако при этом возникает проблема
**первичной кластеризации**, связанной с созданием длинных последовательностей
занятых ячеек.

### Квадратичное исследование

Квадратичное исследование использует хэш-функцию вида

> _h(k, i) = (h'(k) + c1 &sdot; i + c2 &sdot; i^2) mod m_

где _h'_ - вспомогательная хэш-функция, _c1_ и _c2_ - положительные вспомогательные
константы, а _i = 0, 1, ..., m - 1_.
Начальная исследуемая ячейка - _T[h'(k)]_; остальные исследуемые позиции смещены
относительно неё на величины, которые описываются квадратичной зависимостью от номера
исследования _i_.
Для того, чтобы исследование охватило все ячейки, необходим выбор специальных значений
_c1_, _c2_ и _m_.
Если два ключа имеют одну и ту же начальную позицию исследования, то одинаковы и
последовательности исследования в целом, что приводит к **вторичной кластеризации**.

### Двойное хэширование

Двойное хэширование использует хэш-функцию вида

> _h(k, i) = (h1(k) + i &sdot; h2(k)) mod m_

где _h1_ и _h2_ - вспомогательные хэш-функции.
Начальное исследование выполняется в позиции _T[h1(k)]_, а смещение каждой из
последующих исследуемых ячеек равно _h2(k)_ по модулю _m_.
Для того, чтобы последовательность исследования могла охватить всю таблицу, значение
_h2(k)_ должно быть взаимно простым с размером хэш-таблицы _m_.
Удобный способ обеспечить выполнение этого условия состоит в выборе числа _m_,
равного степени 2, и разработке хэш-функции _h2_ таким образом, чтобы она возвращала
только нечётные значения.
Ещё один способ состоит в использовании в качестве _m_ простого числа и построении
хэш-функции _h2_, такой, чтобы она всегда возвращала натуральные числа, меньшие _m_.
Например, можно выбрать простое _m_ и хэш-функции

> _h1(k) = k mod m  
> _h2(k) = 1 + (k mod m')

где _m'_ должно быть немного меньше _m_ (например, _m - 1_).

### Реализация словарных операций

```
search(T, k)
    Вход:
        T: массив хэш-таблицы
        k: объект, содержащий искомые данные (ключ)
    Выход:
        указатель на объект с искомым ключом или NIL

    m := T.length
    i := 0
    repeat
        j := h(k, i)
        if T[j] != NIL и T[j] != DELETED и compare(T[j], k) == 0
            return T[j]
        i := i + 1
    until T[j] == NIL или i == m
    return NIL
```
```
insert(T, k)
    Вход:
        T: массив хэш-таблицы
        k: вставляемый объект

    m := T.length
    i := 0
    repeat
        j := h(k, i)
        if T[j] == NIL или T[j] == DELETED
            T[j] := k
            return
        i := i + 1
    until i == m
    error "Переполнение хэш-таблицы"
```
```
delete(T, k)
    Вход:
        T: массив хэш-таблицы
        k: удаляемый объект

    m := T.length
    i := 0
    repeat
        j := h(k, i)
        if T[j] != NIL и T[j] != DELETED и compare(T[j], k) == 0
            T[j] := DELETED
            return
        i := i + 1
    until T[j] == NIL или i == m
```
