# Основы

## Алгоритмы и структуры данных

**Алгоритм** - любая корректно определённая вычислительная процедура, на **вход** которой подаётся
некоторая величина или набор величин и результатом выполнения которой является **выходная** величина
или набор величин.

Алгоритм - инструмент, предназначенный для решения корректно поставленной **вычислительной задачи**.
В постановке задачи в общих чертах задаются отношения между входом и выходом.

Пример постановки **задачи сортировки**:

> **Вход**: Последовательность из _n_ чисел _\<a1, a2, ..., an>_.  
> **Выход**: Перестановка (переупорядочение) _\<a1', a2', ..., an'>_ входной последовательности,
> такая, что _a1' &le; a2' &le; ... &le; an'_.

Пример постановки **задачи поиска**:

> **Вход**: Последовательность из _n_ чисел _A = \<a1, a2, ..., an>_ и значение _v_.  
> **Выход**: Индекс _i_ такой, что _v = A[i]_, или специальное значение _NIL_, если _v_ в _A_ отсутствует.

**Экземпляр задачи** состоит из входных данных (удовлетворяющих всем ограничениям, наложенным
при постановке задачи), необходимых для решения задачи.

Алгоритм **корректен**, если для любых входных данных результатом его работы являются
корректные выходные данные.

**Структура данных** - это способ хранения и организации данных, облегчающий доступ к этим данным
и их модификацию.

## Инвариант цикла

**Инвариант цикла** позволяет понять, корректно ли работает алгоритм.
Обладает тремя свойствами:

- **Инициализация**: Инвариант справедлив перед первой итерацией цикла.
- **Сохранение**: Если инвариант истинный перед очередной итерацией цикла, то он остаётся истинным и после неё.
- **Завершение**: По завершении цикла инвариант позволяет убедиться в правильности алгоритма.

## Анализ алгоритмов

**Анализ** алгоритма заключается в том, чтобы предсказать требуемые для его выполнения ресурсы
(время вычисления, память, пропускная способность и т.п.).

**Размер входных данных** зависит от рассматриваемой задачи.
Например, для задачи сортировки это _количество входных элементов_ (размер массива _n_);
для задачи на графах это количество вершин и рёбер графа.

**Время работы** алгоритма для тех или иных входных данных измеряется в количестве элементарных
операций, или "шагов", которые необходимо выполнить.

**Наихудший случай** - это максимальное время работы для _любых_ входных данных размером _n_.

**Скорость роста** или **порядок роста** времени работы алгоритма принимает во внимание только
главный член формулы, поскольку при больших значениях _n_ членами меньшего порядка можно пренебречь.
Кроме того, постоянный множитель при главном члене также игнорируется, так как для оценки
вычислительной эффективности алгоритма с входными данными большого объёма он менее важный,
чем порядок роста.

### Асимптотические обозначения

Рассматривая входные данные достаточно больших размеров для оценки только такой величины,
как порядок роста времени работы алгоритма, тем самым изучается **асимтотическая** эффективность алгоритмов.
Это означает, что интересует только то, как время работы алгоритма растёт с увеличением размера
входных данных в _пределе_, когда размер увеличивается до бесконечности.

**Асимптотически положительной** называется такая функция, которая является положительной
при любых достаточно больших _n_.

**&Theta;-обозначение** определяет **асимптотически точную оценку** функции _f(n)_.
Для заданной функции _g(n)_ запись _&Theta;(g(n))_ обозначает _множество функций_

> _&Theta;(g(n))_ = { _f(n)_: существуют положительные константы _c1_, _c2_ и _n0_, такие, что
> _0 &le; c1 &sdot; g(n) &le; f(n) &le; c2 &sdot; g(n)_ для всех _n &ge; n0_ }

Другими словами, для всех _n &ge; n0_ функция _f(n)_ равна функции _g(n)_ с точностью до
постоянного множителя.

Согласно определению _&Theta;(g(n))_ необходимо, чтобы каждый элемент _f(n)_ &isin; _&Theta;(g(n))_,
принадлежащий множеству, был **асимптотически неотрицателен**.

**O-обозначение** определяет **асимптотическую верхнюю границу** и означает множество функций

> _O(g(n))_ = { _f(n)_: существуют положительные константы _c_ и _n0_, такие, что
> _0 &le; f(n) &le; c &sdot; g(n)_ для всех _n &ge; n0_ }

O-обозначения примеяются, когда нужно указать верхнюю границу функции с точностью до
постоянного множителя, т.е. описывают ограничения времени работы алгоритма в наихудшем случае
для _любых_ входных данных.

**&Omega;-обозначение** определяет **асимптотическую нижнюю границу** и означает множество функций

> _&Omega;(g(n))_ = { _f(n)_: существуют положительные константы _c_ и _n0_, такие, что
> _0 &le; c &sdot; g(n) &le; f(n)_ для всех _n &ge; n0_ }

_Теорема_:  
> Для любых двух функций _f(n)_ и _g(n)_: _f(n) = &Theta;(g(n))_ тогда и только тогда,
> когда _f(n) = O(g(n))_ и _f(n) = &Omega;(g(n))_.

Для указания того, что верхняя граница не является асимптотически точной оценкой функции,
применяются **o-обозначения**:

> _o(g(n))_ = { _f(n)_: для любой положительной константы _c > 0_ существует константа _n0 > 0_,
> такая, что _0 &le; f(n) &lt; &sdot; g(n)_ для всех _n &ge; n0_ }

Отличие от O-обозначения в том, что определение _f(n) = O(g(n))_ ограничивает функцию _f(n)_
неравенством _0 &le; f(n) &le; c &sdot; g(n)_ для _некоторой_ константы _c > 0_, а определение _f(n) = o(g(n))_
ограничивает её неравенством _0 &le; f(n) < c &sdot; g(n)_ для _всех_ констант _c > 0_.
В o-обозначениях функция _f(n)_ пренебрежимо мала по сравнению с функцией _g(n)_ при _n_,
стремящемся к бесконечности, т.е.

> _lim (n &rightarrow; &infin;) f(n) / g(n) = 0_

Для указания того, что нижняя граница не является асимптотически точной оценкой функции,
применяются **&omega;-обозначения**:

> _&omega;(g(n))_ = { _f(n)_: для любой положительной константы _c > 0_ существует константа _n0 > 0_,
> такая, что _0 &le; c &sdot; g(n) < f(n)_ для всех _n &ge; n0_ }

В &omega;-обозначениях:

> _lim (n &rightarrow; &infin;) f(n) / g(n) = &infin;_

Для асимптотических обозначений можно провести аналогию между асимптотическим сравнением двух
функций _f_ и _g_ и сравнением двух действительных чисел _a_ и _b_:

> _f(n) = O(g(n))_ аналогично _a &le; b_  
> _f(n) = &Omega;(g(n))_ аналогично _a &ge; b_  
> _f(n) = &Theta;(g(n))_ аналогично _a &equals; b_  
> _f(n) = o(g(n))_ аналогично _a &lt; b_  
> _f(n) = &omega;(g(n))_ аналогично _a &gt; b_

## Рекуррентные соотношения

Метод **декомпозиции** или **"разделяй и властвуй"**: сложная задача разбивается на несколько
простых, которые подобны исходной задаче, но имеют меньший объём; далее эти вспомогательные задачи
решаются _рекурсивным методом_, после чего полученные решения комбинируются для получения решения
исходной задачи.

Три шага метода декомпозиции:
- **Разделение** задачи на несколько подзадач, которые представляют собой меньшие экземпляры той же задачи.
- **Властвование** над подзадачами путём их рекурсивного решения.
  Если размеры подзадач достаточно малы, такие подзадачи могут решаться непосредственно.
- **Комбинирование** решений подзадач в решение исходной задачи.

Когда алгоритм рекурсивно вызывает сам себя, зачастую время его работы можно описать с помощью
**рекуррентного уравнения** (или **рекуррентности**), которое выражает полное время, требующееся
для решения всей задачи размером _n_, через время решения задач для меньших входных данных.

**Рекуррентное соотношение** редставляет собой уравнение или неравенство, которое описывает функцию через
её значения для меньших аргументов.

Пример рекуррентного соотношения для сортировки слиянием:

> _T(n) = &Theta;(1)_, если _n &equals; 1_,  
> _T(n) = 2 &sdot; T(n/2) + &Theta;(n)_, если _n &gt; 1_

Три метода решения рекуррентных соотношений:
- В **методе подстановки** делается предположение о границе, а затем используется метод математической
  индукции для доказательства его корректности.
- В **методе деревьев рекурсии** рекуррентное соотношение преобразуется в дерево, узлы которого
  представляют стоимости на разных уровнях рекурсии.
  Затем для решения рекуррентного соотношения используются методы оценки сумм.
- В **основном методе** граничные оценки рекуррентных соотношений представляются в виде

  > _T(n) = a &sdot; T(n/b) + f(n)_

  где _a &ge; 1_, _b &gt; 1_ - константы, а _f(n)_ - заданная функция.
  Рекуррентное сотношение такого вида описывает алгоритм "разделяй и властвуй", который создаёт
  _a_ подзадач, каждая из которых имеет размер _1/b_ размера исходной задачи, и шаги разделения
  и комбинирования которого в сумме занимают время _f(n)_.

### Основной метод

Основной метод состоит из следующей теоремы:

Пусть _a &ge; 1_, _b &gt; 1_ - константы, _f(n)_ - функция, а _T(n)_ определена на множестве
неотрицательных целых чисел с помощью рекуррентного соотношения

> _T(n) = a &sdot; T(n/b) + f(n)_

где _n/b_ интерпретируется либо как _floor(n/b)_, либо как _ceil(n/b)_.
Тогда _T(n)_ имеет следующие асимптотические границы:
1. Если _f(n) = O(n ^ log (b) a - &epsilon;)_ для некоторой константы _&epsilon; &gt; 0_,
   то _T(n) = &Theta;(n ^ log (b) a)_.
2. Если _f(n) = &Theta;(n ^ log (b) a)_, то _T(n) = &Theta;((n ^ log (b) a) &sdot; lg n)_.
3. Если _f(n) = &Omega;(n ^ log (b) a + &epsilon;)_ для некоторой константы _&epsilon; &gt; 0_
   и если _a &sdot; f(n/b) &le; c &sdot; f(n)_ для некоторой константы _c &lt; 1_
   и всех достаточно больших _n_, то _T(n) = &Theta;(f(n))_.

В первом случае функция _f(n)_ должна быть не просто меньше, чем _n ^ log (b) a_,
а _полиномиально_ меньше (т.е. _f(n)_ должна быть асимптотически меньше _n ^ log (b) a_
на множитель _n ^ &epsilon;_ для некоторой константы _&epsilon; &gt; 0_).
В третьем случае функция _f(n)_ должна быть не просто больше _n ^ log (b) a_,
но полиномиально больше, и к тому же удовлетворять условию "регулярности"
_a &sdot; f(n/b) &le; c &sdot; f(n)_.

## Рандомизированные алгоритмы

**Вероятностный анализ** - это анализ задачи, при котором используются вероятности тех или иных событий.
Чаще всего он используется при определении времени работы алгоритма.
Для проведения вероятностного анализа необходимо располагать знаниями (или следать предположение)
о распределении входных данных.
При этом в ходе анализа алгоритма вычисляется время его работы в среднем случае путём усреднения
времени работы по всем возможным входным данным.
Вычисленное таким образом время работы называется **временем работы в среднем случае**.

В общем случае алгоритм называется **рандомизированным**, если его поведение определяется не только
набором входных величин, но и значениями, которые выдаёт **генератор случайных чисел**.

В ходе анализа времени работы рандомизированного алгоритма получается математическое ожидание
времени работы для распределения значений, возвращаемых генератором случайных чисел.
Такие алгоритмы отличаются от алгоритмов, в которых случайны входные данные, в том смысле,
что время работы рандомизированного алгоритма определяется как **ожидаемое время работы**.
В общем случае говорится о времени работы в среднем случае, когда случайных образом распределены
входные данные алгоритма, и об ожидаемом времени работы, когда случайный выбор делает сам алгоритм.
